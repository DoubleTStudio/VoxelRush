# Task: VR-030 — Grid targeting and ghost UI

## Goal
Aim at the voxel grid in build mode and preview placements. DoD (BACKLOG): invalid placement feedback.

## Prerequisites / relevant docs
VR-020..VR-022. GAMEPLAY_RULES (Building: reach ≤ 6 m, inventory, permission, protected zone, overlap, rate, chunk loaded, never trap a player), CONTROLS_ASSETS (Build mode: ghost is local; server result is authoritative; invalid placement feedback must explain the reason).

## In scope / out of scope
In: engine-free voxel raycast (grid traversal), shared `EditValidator` with stable reason codes and messages, client `BuildTargeting` (ghost + feedback label), terrain as an `IEditWorld`, preview-scene wiring, DoD tests.
Out: sending/applying edits and per-user rate limit (VR-031), inventory (later), permissions/roles (SAVE-004), orbit camera, hotbar and rotate (build-mode UX polish), Client.unity integration (needs the client voxel world, follows the VR-023 integration).

## Public interfaces and contracts
- `VoxelRaycast.Cast(origin, direction, maxDistance, isSolid, out VoxelHit)`: Amanatides–Woo, face-adjacent steps, bounded (~3 cells per metre); `VoxelHit.Block` (Remove target), `.Adjacent` (Place target), entry normal, distance.
- `EditValidator(protectedZones, reach = 6)`: `Validate(action, target, blockType, actorEye, world, occupants)`. **Fixed check order**: invalid block type → reach (to the block's nearest point) → protected zone → chunk loaded → occupied / nothing to remove → overlaps player. `RateLimited` is reserved for the server's per-user limiter. `Describe` (player-facing text), `ReasonCode` (stable snake_case for logs/wire).
- `IEditWorld` (`IsLoaded`, `GetBlock`), `WorldBox`, `EditAction`, `EditRejection`.
- Presentation: `BuildTargeting` (`Action`, `BlockType`, `AimPoint`, `Target`, `Rejection`, `FeedbackText`, `GhostColor`, `Refresh()`); `VoxelTerrainView` implements `IEditWorld` and `IsSolid`.

## Tests
- Domain: raycast axis/negative/diagonal (every crossed cell, face-adjacent steps), start-inside, max distance, degenerate input, bounded traversal; validator accept, reach to block surface, protected zone, occupied, nothing to remove, player trapping, unloaded chunk, invalid block, stable check order, every reason has message + code.
- PlayMode (`BuildTargetingTests`, VoxelPreview scene, real generated terrain): **DoD**: within reach → green ghost, "Place block"; 12 m up → red, reach message; protected spawn column → red, protection message; remove mode targets the hit block; aiming at sky hides the ghost.

## Bugs found during validation (fixed)
- Test isolation: NUnit reuses a fixture instance; mutable world state leaked between validator tests (now reset per test).
- A diagonal-ray test expected a cell the line only touches at a corner (geometry corrected; the test now asserts every crossed cell in order).
