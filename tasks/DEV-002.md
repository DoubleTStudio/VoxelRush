# Task: DEV-002 — Object storage for the local online stack

## Goal
Snapshot uploads and downloads should work in `tools/dev-online.sh` as they do against R2 in production. Before this change the dev stack had no S3-compatible store, so the snapshot endpoints answered `501 storage_disabled` and worlds lived only on local disk (DEV-001 "Not done").

## Changes
- **`docker/compose.dev.yaml`**: new `s3` service (SeaweedFS 3.97, the S3 gateway the API tests and smokes already use; MinIO images left Docker Hub).
  - Runs in the same compose project as `db`, with its own named volume `voxelrush-s3`.
  - Published on `127.0.0.1:${VOXELRUSH_DEV_S3_PORT:-18092}` only. The user's standalone `minio` container is not used.
  - The S3 identity comes from an inline compose `config` interpolated from `VOXELRUSH_DEV_S3_ACCESS_KEY`/`SECRET_KEY`, so the keys are on no command line and in no file other than the secrets file.
  - The network name is `${VOXELRUSH_DEV_NETWORK:-voxelrush-dev}`, so a second project gets its own network.
- **`tools/dev-online.sh`**:
  - `up` starts `db` and `s3`, waits for the S3 gateway, and passes `VoxelRush__Snapshots__ServiceUrl=http://127.0.0.1:$S3_PORT`, the bucket and the keys to the API by environment. The API creates the bucket at startup (`EnsureBucketAsync`).
  - Native world servers reach the same loopback address that presigned URLs carry.
  - Two storage keys are generated into the gitignored `secrets.env` (600). An existing file gains only the missing keys, so the database password stays valid.
  - New `check` command: guest and world, lease (service token), upload URL, presigned PUT, commit, `latest` (revision and SHA-256), presigned GET compared with the SHA-256, then lease release and world deletion. Tokens and presigned URLs reach curl through `-K` configs on pipes, never its argv.
  - New overrides for running a second stack side by side: `DEV_PROJECT`, which sets the compose project, the network, and the state directory `artifacts/dev-online-<name>/` (default project and paths unchanged); `S3_PORT`; and `PORT_RANGE_START`/`PORT_RANGE_END` for the host agent's UDP range.
  - `status` shows `db` and `s3` separately, and `down` keeps both volumes.
- **API** (`ApiOptions`): `SnapshotStoreOptions.Validate()` runs at startup. With a `ServiceUrl` set, a non-absolute or non-http(s) URL, empty keys or an empty bucket now fail at boot instead of on the first upload. An empty `ServiceUrl` still disables storage.
- **Docs**: the DEPLOYMENT.md "Local online stack" section (storage row, `check`, overrides, secrets, the local world copy is now a cache, fail-closed note), the snapshot storage settings paragraph, and the README command line.

## Not done
- Periodic snapshots while a world runs: servers still upload only at clean shutdown (SAVE-003 scope), so a crash or `kill -9` loses edits made since the last clean stop if the local world directory is also deleted.
- The playtest stack (`voxelrush-dev`) wasn't restarted. It picks up storage on its next `down`/`up`; its existing `secrets.env` gains the two storage keys then.
- `check` leaves its soft-deleted world and its 2 KiB object behind, since there is no garbage collection for deleted worlds.

Found while testing: a join that lands while a world server is in its final second of idle shutdown (lease released, process not yet exited) gets `200` with the dying server's endpoint, and the client times out. The host agent sees the process still alive. This is pre-existing ALLOC-001/DEV-001 behaviour and is not changed here. Retrying the join after the process exits starts a fresh server.

## Risks / rollback
- Storage is now on the dev stack's critical path: if the `s3` container is down, world servers fail closed at start (SAVE-003). `down` + `up` brings it back.
- SeaweedFS turns read-only when the Docker disk is nearly full (SAVE-009 note). The low free-space floor (`-volume.minFreeSpace=50MiB`) keeps it writable until close to full. If uploads fail, `world_snapshots_published … failed>0` shows it, and the uploads retry at the next shutdown.
- The keys sit in `artifacts/dev-online/secrets.env` (600) and in the API process environment, like the other dev secrets. Storage listens on loopback only.
- Rollback: revert the commit. `down` removes the `s3` container either way. `docker volume rm voxelrush-dev_voxelrush-s3` drops stored snapshots, and worlds keep their local copies.
