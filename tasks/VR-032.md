# Task: VR-032 — Durable journal and snapshot/recovery

## Goal
Acknowledged edits survive crashes. DoD (BACKLOG): crash recovery, no lost acknowledged edits.

## Prerequisites / relevant docs
VR-031 (`WorldAuthority`). ADR-007 (journal + verified snapshots), PERSISTENCE_SECURITY (Commit protocol: never acknowledge before durable journal commit; Snapshotting; Concurrency: async persistence with backpressure), SAVE_GAME_CLOUD_PERSISTENCE (kill after/before ACK, shutdown drain), AGENTS (no blocking storage on the tick), SYSTEM (first slice: file persistence).

## In scope / out of scope
In: journal record format (length + CRC-32 + versioned binary), background group-committing `JournalWriter` with bounded queue and durable notifications, recovery with torn/corrupt-tail truncation, edits-only chunk snapshots (checksum + content hash, atomic publish, read-back verification), corrupt-snapshot rejection, journal-gap detection, idempotency re-seeding after restart, authority gating on journal capacity, process-kill crash test in CI.
Out: journal compaction/pruning after snapshots (SAVE-003; the journal currently grows), object storage and compression (SAVE-003/VR-080), multi-chunk atomic manifests (DES-004), leases/fencing (SAVE-005), directory fsync after rename, wiring into the server's network loop (VR-033).

## Public interfaces and contracts
- `JournalCodec` (record v1: operation id, actor, chunk, base/new revision, tick, changes; ≤ 64 KiB payload; decoder bounds-checks indices and revisions), `Crc32`.
- `JournalWriter : IMutationSink`: `CanAccept`, `TryEnqueue`, `DrainDurable` (acknowledge only these), `Pending`, `Failure`, graceful `Dispose` (drain + flush + close). One fsync per group.
- `IMutationSink` (Editing): the authority checks `CanAccept` **before** applying; refusal = new transient `persistence_backpressure`.
- `WorldStore`: `RecoverJournal` (truncate invalid tail), `LoadChunk` (verified snapshot + journal records after its revision, `baseRevision` must chain), `WriteSnapshot` (temp → fsync → atomic replace → verify), `KnownChunks`, `Problems`, `RejectedSnapshots`, `TruncatedBytes`. Snapshot file names are integer-only (no path traversal).
- `WorldAuthority.RememberRecovered(records)`: retries of durable-but-unacknowledged operations return the original result.
- `ChunkData.FromSnapshot`.

## Bugs found during validation (fixed)
- **Revision applied before durability was guaranteed.** The first SIGKILL run lost 27,008 acknowledged edits: under backpressure the authority had already advanced the chunk revision when the journal refused the batch, leaving a gap (`journal gap at revision 136`) that stops replay. The authority now asks the sink before applying and refuses with `persistence_backpressure`.

## Tests
- Domain (`PersistenceTests`): codec round trip; durable reporting in order; replay onto generated base; torn tails of 1/5/11 bytes truncated; corrupt middle record stops replay; snapshot + later journal; corrupt snapshot rejected → rebuilt from journal; journal gap reported; post-crash retry idempotent; backpressure refuses; authority refuses before applying when the sink is full; integer-only snapshot names.
- **DoD** `tools/crash-test.sh N`: a harness process edits two chunks through the authority, prints ACK only for durable batches, snapshots only fully durable state, and is SIGKILLed after a random 0.4–2.0 s; after each kill, recovery must contain every ACKed operation at or beyond its acknowledged revision with no problems.
