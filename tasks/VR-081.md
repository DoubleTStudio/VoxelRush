# Task: VR-081 — CI signing, staged release, monitoring and rollback drill

## Goal
Signed builds reach testers from CI; server releases move through channels and can be rolled back safely. DoD (BACKLOG): internal beta installs.

## Prerequisites / relevant docs
VR-003 (CI), VR-080 (API image), ADR-013 (Firebase App Distribution). DEPLOYMENT (CI stages, secrets, rollback, monitoring). Runbooks: `docs/operations/RELEASE.md`, `docs/operations/MONITORING.md`.

## In scope / out of scope
In: `Editor/ReleaseSettings` (upload-key signing and version/build number from environment variables, applied only for the build and restored; `-releaseBuild` refuses a debug key), `tools/build.sh --release`, `.github/workflows/release.yml` (secret-gated: signed Android APK + `apksigner verify`, iOS Ad Hoc archive/export with a temporary keychain, upload to Firebase App Distribution with pinned `firebase-tools`), image version labels (`tools/image-labels.sh`), `tools/rollback-check.sh`, `tools/rollback-drill.sh` (Docker and native modes), `tools/publish-images.sh` (CI on `main`: drill against the previous `:main`, push `:sha-*` and `:main` to GHCR), `tools/promote-image.sh` (staging/beta/production, rollback = promote an older sha), `tools/check-server-log.sh` + alert table, CI log-alert step.
Out: Play internal track/AAB and TestFlight (beta/production), a staging host to deploy to, OIDC keyless Firebase auth, log shipping configuration for a specific provider.

## Blockers (DoD)
**Internal beta installs: blocked** — no Firebase project, service account, Android upload keystore, Apple Developer membership/certificates or tester devices are available here. Setup steps are in `docs/operations/RELEASE.md`; the release workflow skips each platform with a visible warning until its secrets exist.

## Issues found during validation (fixed)
- Restoring an empty keystore path makes Unity serialize `'{inproject}: '`, so test runs dirtied ProjectSettings; the normalized empty value is now the committed baseline (getter value unchanged), and later runs leave the file untouched.
- `GROUPS` is a bash built-in array; the tester-group variable is `TESTER_GROUPS` (shellcheck).

## Tests and evidence
- EditMode `ReleaseSettingsTests`: no-environment dev builds valid, release without keystore refused; keystore needs an existing file and all passwords; version/build-number validation; `Apply` fully restored on dispose and passwords cleared.
- **Signed build locally**: throwaway keystore from Unity's bundled `keytool`; `tools/build.sh android --release` without a key → refused ("Release builds need the upload keystore"); with the key → APK verified by `apksigner` (signer `CN=VoxelRush Test Upload`), `versionCode=123`, `versionName=0.9.1`; the password appears in neither the build log nor ProjectSettings; keystore deleted.
