# Task: DES-003 — Vehicle collision damage and contact dedup

## Goal
Car impacts damage blocks, once per impact. DoD (BACKLOG): one impact one damage window.

## Prerequisites / relevant docs
DES-001 (materials, sparse HP), DES-002 (zones). DESTRUCTION (Sources/Collision: energy = ½·m·v² on the normal, threshold, scale, clamp, integer; HP: dedup by actor/target/contact window; Tests: repeated contact, concurrent hits, cross-chunk border, malicious client damage).

## In scope / out of scope
In: `CollisionDamageModel`, `ContactDeduplicator` (bounded by `Prune`), `ImpactResolver` (model → zone → dedup → HP).
Out: feeding PhysX contacts from server cars into the resolver — the server has no voxel colliders yet (the plot is data-only, ADR-016); that hookup lands with server colliders (DES-012) and needs HP replication/journaling (journal record v2). Vehicle self-damage, VFX/audio.

## Parameters (placeholders, tune in playtests)
Threshold 8 kJ (a 1,200 kg car at ~3.7 m/s), 2 HP per kJ above it, max 150 HP per impact, window 0.3 s. Example: 1,200 kg at 10 m/s → 104 HP (a stone block survives one hit, a reinforced block needs three).

## Security
Inputs are server physics (relative normal speed, server mass); clients never send damage, so there is no "malicious damage amount" path to validate. NaN/negative mass → 0; infinite speed clamps.

## Tests (`Tests/Domain/Destruction/CollisionDamageTests.cs`)
Threshold, v² growth + clamp + integer, NaN/zero/negative/∞ safety, model validation; dedup per actor and per target with expiry; prune bounds memory; **DoD**: 9 consecutive contacts (0.3 s at 30 Hz) → exactly one damage application, a bounce after the window is a second impact; two cars hitting together both count; cross-chunk-border hits damage each block in its own chunk; protected/live-track blocks untouched and don't open windows; grazes don't open windows; mismatched chunk throws.
