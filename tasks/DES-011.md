# Task: DES-011 — Incremental bounded collapse scheduler

## Goal
Unsupported player-built structures fall, without any tick doing unbounded work. DoD (BACKLOG): queue caps under stress.

## Prerequisites / relevant docs
DES-010 (support search), DES-004 (server commits), VR-033 (replication). DESTRUCTION (Structure: bounded BFS on deletion, incremental work queue; initial caps 512 checks/tick, 256 removed blocks/collapse, 4 active jobs/world; until resolution mark the affected region blocked/non-interactive; avoid unbounded cascades).

## In scope / out of scope
In: resumable `SupportSearch` (DES-010's analyzer now runs on it), `CollapseScheduler` + `CollapseLimits`, `WorldAuthority.IsBlocked` hook and `structure_settling` (transient) rejection, server integration (`WorldSyncServer` enqueues accepted removals, ticks the scheduler, refuses new removals with `server_busy` while saturated, logs `world_collapse` and totals), tower bot (`-botTower H`) and a networked collapse check in `tools/smoke-world.sh`.
Out: re-running analysis for jobs pending at a crash (see risks), collapse VFX beyond normal debris, collider rebuild priority (DES-012), explosions feeding the scheduler (no gameplay trigger yet; `Enqueue` is the hook).

## Design notes
- Each removal point is a job probing its six neighbours (1 check each) and searching every player-built neighbour's component; up to 4 jobs share 512 checks per tick round-robin. Components found in a job are claimed so they're reported once.
- Disconnected components queue for removal; at most 256 blocks per tick are committed through `CommitServerChanges` (journaled, replicated like any edit). Blocks changed meanwhile (e.g. blown up) are skipped. Journal backpressure re-queues the batch; the region stays blocked.
- No cascades by construction: a disconnected component contains every face-connected player-built block, so removing it can't unsupport anything else.
- Blocked for client edits: blocks queued for removal, within one block of a pending point, and within one block of an active search's explored bounds (so nobody can re-anchor or extend a structure mid-analysis).
- Pending removal points are capped (1,024); when full, `Enqueue` refuses and the server rejects new removals. A search beyond 65,536 checks is abandoned as supported and counted.

- Domain (`CollapseSchedulerTests`): tower cut at the base collapses through journaled batches; supported bridge stays; **DoD stress**: 64 eight-block towers under a 24×24 deck, all bases cut, plus 1,500 extra removal points → pending capped at 1,024 (540 refused), every tick ≤ 512 checks, ≤ 256 removed (cap bound), ≤ 4 active jobs; 1,024 blocks removed (tower remnants + deck) in 24 ticks, **zero floating player-built blocks** afterwards, anchored hut untouched, nothing abandoned, replica hashes equal the server's; settling region rejects client edits until done while elsewhere is fine; journal backpressure retries; oversized search abandoned; pre-changed blocks left alone; enqueue de-duplication.
- DES-010 tests unchanged and passing on the resumable search.
