# Task: DEV-001 — Local online stack on a macOS development machine

## Goal
Run the ALLOC-001 join flow (sign in, create/list worlds, join with a per-world server) on an Apple Silicon Mac with one command, so a phone on the LAN or Tailscale can play against it. The host agent only launched Linux amd64 containers, and that server crashes under emulation on arm64 (Mono JIT, ADR-012). A native `build/server-mac` build already runs there.

## Changes
- **Host agent process runtime** (`backend/VoxelRush.HostAgent/ProcessRuntime.cs`): `ProcessRuntime` implements `IContainerRuntime` with native server processes. It is selected by `HostAgent:Runtime=process` with `HostAgent:ServerExecutable` and `HostAgent:WorldDataRoot` (absolute paths). Docker stays the default.
  - Same `WorldHosts` logic as containers: names `voxelrush-world-{id:N}`, port range, `MaxWorlds`, ready on `event=server_listening` in stdout, start timeout, port held by another process skipped (UDP bind probe).
  - Per world: `-port {hostPort} -worldDir {WorldDataRoot}/voxelrush-world-{id:N}` (after `-batchmode -nographics -logFile -`). Stdout and stderr are appended to `{WorldDataRoot}/voxelrush-world-{id:N}.log`.
  - Process exit means stopped (slot and port freed). A hung boot is killed. On agent shutdown (host disposal) servers get SIGTERM, and any still running after 15 s are killed.
  - Secrets (`VOXELRUSH_TICKET_KEY`, `VOXELRUSH_API_URL`, `VOXELRUSH_SERVICE_TOKEN`) go only into the child's environment. The agent's own `HostAgent__*` variables are removed from it.
  - `IProcessLauncher` separates the OS (`OsProcessLauncher`) from the runtime, so tests use a fake.
- **Runtime contract**: `IContainerRuntime.ServerBinding(hostPort, volume)` supplies the server's `-port`/`-worldDir`. Its default implementation keeps containers on `7777` and `/data`.
- **Options**: `Runtime`, `ServerExecutable`, `WorldDataRoot`. `ServerImage` is required only for docker. Unknown runtimes and relative paths are rejected at startup, as is a missing executable (`Program.cs`).
- **`tools/dev-online.sh up|down|status`**:
  - PostgreSQL comes from the `db` service of `docker/compose.backend.yaml` plus the new `docker/compose.dev.yaml` (project `voxelrush-dev`, own network, `127.0.0.1:15434`).
  - The API runs natively on `0.0.0.0:18090`; the host agent runs natively on `127.0.0.1:18091` with the process runtime.
  - `PUBLIC_HOST` defaults to the Tailscale IPv4, else the LAN IP. `SERVER_EXE` overrides the server build (built via `tools/build.sh server-mac` if missing).
  - Secrets are generated once into `artifacts/dev-online/secrets.env` (600, gitignored) and passed by environment only. `down` stops only what `up` started and keeps the volume.
- **CI**: the changed-areas filter treats `tools/dev-online.sh` and `docker/compose.dev.yaml` as backend-only.
- **Docs**: "Local online stack (macOS)" in `docs/operations/DEPLOYMENT.md`, new configuration rows, README command line.

## Not done
- Object storage in the dev stack: snapshot endpoints answer `501 storage_disabled`, so worlds stay on local disk.
- The client's handling of `202`/`503` from join (ALLOC-001 "Not done") and testing from a real phone. Verified with curl and the macOS bot only.
- Adopting running servers after an agent restart (process mode keeps no labels). `down` cleans up orphans instead.
- A Linux arm64 server image, which would make the container runtime usable on Apple Silicon.

## Risks / rollback
- No container isolation: world servers run as the developer's user with full filesystem access. Process mode is for development machines only.
- The API listens on all interfaces with generated secrets. Anyone on the LAN/Tailnet can create guest accounts while the stack is up. Run `down` when not playtesting.
- macOS may prompt to allow incoming connections for `dotnet` and `VoxelRush`; if denied, phones can't connect.
- If the agent dies hard, its servers lose their log output until `down` stops them.
- Rollback: `tools/dev-online.sh down`; revert the commit. Docker runtime behaviour is unchanged (existing tests pass with the same container arguments); no schema changes.
