# Task: CI-003 — PR Unity runs only on request

## Goal
Stop pull requests from evicting main's pending full suite from the single Unity license queue.

## Problem
Every Unity job (CI and release) shares the `unity-personal-license` concurrency group. GitHub keeps one pending job per group, so a PR pushed while main's full suite waits replaces it, and main's iOS compile, rollback drill and image publish never run.

## Changes
- `ci.yml` `unity` job: on `pull_request` it runs only when the PR carries the `unity-ci` label (fast gate) or `full-ci` (full suite). Pushes to main and manual runs are unchanged.
- Unlabelled PRs still run domain tests, the secret scan, API and host-agent tests; Unity tests run locally (`tools/test.sh editmode|playmode`) before review.
- Adding a label re-triggers CI (`labeled` is already a trigger type).

## Verification
- actionlint 1.7.7 clean on `ci.yml`.

## Risks / rollback
A Unity regression on an unlabelled PR is caught on main instead of on the PR. Rollback: revert.
