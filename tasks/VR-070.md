# Task: VR-070 — Burst/job meshing and main-thread budgets

## Goal
Cheaper chunk meshing so collider (and later render) rebuilds fit the tick and frame budgets. DoD (BACKLOG): profile captured.

## Prerequisites / relevant docs
VR-022 (greedy mesher), VR-023/DES-012 (collider rebuilds before physics), PERFORMANCE (mobile budgets), AGENTS (bounded tick work), skills/voxel-engine.

## In scope / out of scope
In: `BurstChunkMesher` (Burst `IJob`, same algorithm and output as the managed mesher; `Build` on the calling thread, `Schedule`/`Complete` for workers), streamer collider builds on it (native buffers straight into the mesh), allocation fixes found by profiling, golden/equality tests, the profile.
Out: render-mesh building on clients (no synced-plot rendering yet; `Schedule` is ready for it), cooking colliders on workers (`Physics.BakeMesh` in a job — next lever, see profile), device profiling (VR-071, needs devices).

## Findings and fixes
1. `ChunkMeshData.AddQuad` allocated two arrays per quad (the "no allocation" comment was wrong). Fixed with an allocation-free axis helper.
2. `ChunkData.CopyEffectiveBlocks`/`Get` enumerated/looked up a `SortedDictionary` (its enumerator allocates; 7 calls per mesh). `ChunkData` now keeps an effective-block array in step with the edit map: O(1) `Get`, allocation-free copies, +4 KiB per loaded chunk. The managed mesher is now verified allocation-free after warm-up.
3. Burst job: safety checks disabled for this job (bounds proven by the equality tests; players compile them out anyway) and stride arithmetic instead of dynamic `int3` indexing: 1.4× → **4.8×**.

## Profile (`docs/perf/VR-070-meshing-profile.json`, Apple M3, editor EditMode, 147 terrain chunks, mean 157.5 quads/chunk)
| Per chunk | ms |
|---|---|
| Managed greedy mesher | 0.266 |
| Burst mesher (calling thread) | **0.056** (4.8×) |
| Padded fill (main thread) | 0.020 |
| Scheduled build, main-thread share | **0.024** |
| PhysX collider cooking | 0.075 |
With the default collider budget (2 per step) a collider rebuild now costs ≈ 0.13 ms each, i.e. ~0.26 ms of the 33 ms server tick; cooking is the larger half.
