# Task: VR-012 — NGO connection, input sequencing, server authority, prediction/reconciliation

## Goal
Server-authoritative networked cars with client prediction. DoD (BACKLOG): two cars under 100 ms RTT.

## Prerequisites / relevant docs
VR-002 (connection/admission), VR-010 (input), VR-011 (vehicle). ADR-002, ADR-008, VEHICLE_NETWORKING, CONTRACTS (ClientInput, VehicleSnapshot), QUALITY_GATES (M1 network driving). Decisions: `docs/adr/ADR-015-authoritative-vehicle-netcode.md`.

## In scope / out of scope
In: 30 Hz tick loop with scripted physics, sequenced redundant input, server input validation/rate limiting, snapshots, owner prediction + restore/replay reconciliation, remote interpolation, per-player spawning, bots (driving + cheating), dev network-condition simulation, drive smoke test in CI.
Out: client clock sync and input-delay tuning, interest management (VR-072), 8-player load and tick metrics (VR-013), join tickets (VR-080), follow camera/HUD speedometer (VR-062), reconnect (VR-062), loss/jitter acceptance at 2% (VR-072).

## Public interfaces and contracts
- Core: `InputCommand`, `ClientInputHistory`, `ServerInputQueue` + `InputRejection`, `CorrectionPolicy`, `TickClock`, `DelayLine<T>`, `NetworkConditionOptions`, `IDrivingInputSource`.
- Gameplay: `ArcadeVehicle.Simulate(dt)`, `AutoSimulate`, `CaptureState()`/`RestoreState()`, `VehicleState`, `BoostState`.
- Networking: `NetworkSimulation`/`ITickParticipant`, `VehicleNetworkDriver` (`SubmitInputsRpc` owner-only unreliable, `SnapshotRpc` unreliable 15 Hz), `InputBatch` (≤ 4 commands), `VehicleSnapshot`, `SnapshotInterpolator`, `VehicleSpawner`, `BotInputSource` (`-botDrive`), `BotCheater` (`-botCheat`, dev builds only).
- Logs: `vehicle_spawned`, `vehicle_server_stats`, `vehicle_prediction_stats`, `vehicle_remote_stats`, `vehicle_input_abuse_disconnect`, `network_conditions`, `bot_cheat_sent`.
- Assets: `Prefabs/Arena.prefab` (in Server/Client/Bot scenes, 8 spawn points), `Resources/Network/NetworkedCar.prefab`.

## Failure modes / security
- Spoofed actor: owner-only RPC plus sender re-check (`rejectedSpoofed`).
- Speed hack / malformed values: rejected before simulation; car speed unaffected (verified).
- Replay/old sequences: ignored; far-future sequences and floods rejected; queue bounded; abusive clients disconnected.
- Starvation/disconnect: last input repeats ≤ 6 ticks, then neutral.
- Hostile snapshot values: non-finite states refused by `RestoreState`; `InputBatch` length capped before allocation.

## Tests
- Domain: input history, server queue (ordering, duplicates, speed hack, far-future, rate limit, capacity, starvation), correction policy, tick clock, delay line (delay, order, jitter bounds, seeded loss), network-condition parsing.
- EditMode: snapshot interpolation (interpolate, out-of-order, teleport, extrapolation cap), boost capture/restore, networked prefab and Arena wiring in all three scenes.
- PlayMode: `CaptureRestoreReplay_ReproducesTrajectory` (restore + replay of 45 ticks matches within 1 cm / 0.5° / 0.01 m/s).
- **DoD** `tools/smoke-drive.sh`: server + two dev bots at 100 ms RTT, one also cheating.
