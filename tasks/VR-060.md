## Rules implemented
- Progress only from server physics samples (`ReportMovement(from, to, tick, respawned)`), only for the **next** gate, only forwards, only inside its bounds; crossing any other gate is ignored.
- **Minimum progression time**: a crossing sooner than `distance (minus gate half-widths) / maxPlausibleSpeed` after the previous checkpoint (or the start signal) is `TooFast`.
- **Teleport**: more than `maxPlausibleSpeed / 30 · 1.5 + 1 m` in one tick without a server respawn is `Teleported`; nothing counts that sample.
- **Respawn history**: server respawns are counted and never count as crossings.
- Client finish claims are always refused (`ClaimFinishFromClient` → false, counted).
- Results: finishers by time, then DNFs by progress; finishing window 30 s after the first finisher; a race with no finisher ends after 10 min; reset clears progress and keeps the roster.
