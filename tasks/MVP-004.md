# Task: MVP-004 — Online play from the phone

## Goal
A phone player can sign in, see and create worlds, and join one through the API with a signed join ticket, not only a development server address.

## Changes
- **PlayerApi** (Networking/Online): guest sign-in, resumed on later launches with the stored refresh token (rotated on every refresh). Also lists my and public worlds, creates a world, and joins one. An expired access token is refreshed once on 401 and the call retried. While a world's server is starting (ALLOC-001 202 `retryAfterSeconds`), join waits up to 90 s. API failures become short player-facing messages.
- **Transport:** `UnityApiTransport` (UnityWebRequest, so it works on Android and iOS) behind `IApiTransport`, so tests use a scripted fake. Refresh tokens are stored in PlayerPrefs, keyed by API URL (`PrefsTokenStore`).
- **Join screen:** a second panel with the API address (remembered), Sign in / Refresh worlds, Create, and a Join button per world. Joining passes the ticket to `ClientNetwork.Connect(endpoint, ticket)`.
- **Reconnect** in online mode asks the API for a fresh ticket, because tickets are single-use (`TicketVerifier` rejects replays).
- **Player settings:** `insecureHttpOption = DevelopmentOnly`, so development builds can reach a LAN or Tailscale API over HTTP; release builds need HTTPS.

## Not done
- Platform secure storage for the refresh token (Keychain/Keystore).
- Account linking UI (`/v1/auth/link-code`, `/link`) and invites.
