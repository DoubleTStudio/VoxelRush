# Task: VR-062 — Lobby, race HUD, results and reconnect

## Goal
A full race on the dedicated server with real (bot) clients. DoD (BACKLOG): 8-player race flow.

## Prerequisites / relevant docs
VR-060 (race authority), VR-061 (overlay), VR-012 (server cars), VR-002 (handshake). GAMEPLAY_RULES (race states, checkpoints), VEHICLE_NETWORKING (authoritative crossings, reconnection test), CONTRACTS (RaceState), CONTROLS_ASSETS (HUD). Decisions: `docs/adr/ADR-017-race-flow-and-sessions.md`.

## In scope / out of scope
In: protocol 2 handshake with session id (`ConnectionPayload`, `ConnectionGate.SessionOf`, `session_in_use`); `RaceAuthority` reconnect rules and respawn pose; race codecs (`TrackMessage`, `RaceProgressMessage`, `RaceResultsMessage`) and `RaceAutopilot` (bots only); `RaceServer`/`RaceClient` on NGO; `ArenaTrack`; `-raceAutoStart N`; grid placement at countdown; clean `ClientBootstrap.Reconnect`; bots `-botRace` and `-botReconnectAfterGate K`; `RaceHud` (engine-free `RaceHudModel` + UGUI) in `Client.unity`; `tools/smoke-race.sh` in CI.
Out: lobby UI with ready buttons and race selection (dev auto-start only), match overlay on the network (VR-061 overlay is server-side ready; destructible track tagging pending), authored tracks, camera/minimap, persistence of results and rewards (SAVE-006/ECON), join tickets (VR-080).

## Bugs/issues found during validation (fixed)
- Auto-start re-armed after each reset, so races ran back to back with cars wherever the last race left them: the server now places all racers on the start grid at every countdown; the smoke test checks the first race and that a second countdown follows.

## Tests
- Domain: gate sessions (round trip, legacy v1 → mismatch, empty session, duplicate session refused until released, same id/different session); race reconnect (progress kept, no samples while away, resume + respawn pose, grace expiry, unknown racer, disconnected racers don't block results, everyone gone ends the race); codecs (round trip, truncation, trailing bytes, invalid tracks, name truncation, entry caps); autopilot; HUD model (countdown, checkpoint feedback, finished, results with DNF and "you", time format); `-raceAutoStart` parsing.
- EditMode: `Client.unity` contains exactly one `RaceHud`. PlayMode: HUD follows countdown → checkpoints → results on a real canvas.
- **DoD** `tools/smoke-race.sh native`: server with `-raceAutoStart 8` + 8 racing bots; countdown with 8 racers, Countdown → Racing → Finishing → Results; bot 3 drops after gate 1 and resumes (`race_reconnected`, its spawn judged `Respawned`), **8/8 finished**, no legitimate bot flagged (`TooFast`/`Teleported`), every bot's results equal the server's and each finds itself; a second countdown follows the reset.
