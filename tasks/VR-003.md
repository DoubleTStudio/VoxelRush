# Task: VR-003 — Domain CI + Unity test runners + GitHub Actions

## Goal
A GitHub Actions pipeline running every test tier and the three builds. DoD (BACKLOG): green test pipeline.

## Prerequisites / relevant docs
VR-001 (project, `tools/*.sh`, build entry points). QUALITY_GATES (CI), DEPLOYMENT (CI pipeline stages, Secrets), kit `.github/workflows/README.md` ("do not commit a pretend-green workflow").

## In scope / out of scope
In: `.github/workflows/ci.yml` with domain tests and one Unity job (EditMode/PlayMode, Linux server build + smoke, Android APK, iOS Xcode project) plus an unsigned iOS compile; license gating; artifacts.
Out: Docker image publish and staging deploy (VR-002 onward), signing and store/tester distribution (VR-081), device benchmarks.

## Public interfaces and contracts
- Required secrets: `UNITY_EMAIL`, `UNITY_PASSWORD` (Unity ID with a free Personal license, 2FA off).
- Artifacts: `domain-test-results`, `unity-test-results-and-logs`, `server-linux64` (7 days), `android-apk` (7 days), `ios-xcode-project` (1 day).
- `tools/unity.sh` accepts `UNITY_EDITOR` or `UNITY_EDITOR_PATH` (binary, `.app` or install dir); `tools/test.sh` honours `UNITY_TEST_BUILD_TARGET` (empty skips the target switch).

## Implementation steps
1. Domain job: `actions/setup-dotnet` from `global.json`, `tools/test.sh domain`.
2. `unity-license` gate job: the Unity job shows as skipped plus a warning when secrets are missing.
3. GameCI was evaluated and rejected: its Linux activation (unity-builder v4.8.2 `activate.sh`) only supports a serial or a license server. Unity 6 Personal activations produce a machine-bound `UnityEntitlementLicense.xml` with no serial or `.ulf`, so free Personal licenses can't activate there.
4. Instead, one hosted Ubuntu job installs the pinned editor with `RageAgainstThePixel/unity-setup` v2.6.0 (modules from build targets + `linux-server`) and activates Personal with `RageAgainstThePixel/activate-unity-license` v2.2.2, whose post step returns the seat.
5. A single job plus `concurrency: unity-personal-license` keeps one activation in use at a time.
6. Steps call the same `tools/test.sh` / `tools/build.sh` / `tools/smoke-server.sh` as local runs; builds go through `BuildEntryPoints`, so configuration validation gates them.
7. Server smoke runs on the native x86-64 runner (covers the Rosetta gap from VR-001).
8. iOS only on `main`/manual: Xcode project built in the Unity job, tarred, compiled unsigned on `macos-15`.

## Failure modes / security concerns
- `permissions: contents: read`; secrets passed only as step env to the Unity steps; actions pinned to SHAs.
- `concurrency` cancels superseded runs; every job has `timeout-minutes`.
- Library cache keyed on `packages-lock.json` + editor version, per build target.
