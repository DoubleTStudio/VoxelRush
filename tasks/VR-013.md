# Task: VR-013 — 8-player headless load fixture, telemetry

## Goal
Measure the authoritative server's 30 Hz tick with 8 players. DoD (BACKLOG): recorded 30 Hz tick metrics.

## Prerequisites / relevant docs
VR-012 (bots, netcode), SYSTEM.md (Execution, Observability), QUALITY_GATES (M1: 8-player load target; Performance: server 30 Hz at 8 players).

## In scope / out of scope
In: tick work timing, percentiles/overruns/achieved rate, periodic server metrics log, snapshot fan-out counter, 8-bot load fixture with assertions, recorded baseline, CI step (main/manual).
Out: bandwidth/packets per second and interest management (VR-072), memory/GC profiling (VR-070), device-tier client benchmarks (VR-071), metrics export to a monitoring backend (VR-081).

## Public interfaces and contracts
- `TickMetrics` / `TickWindow` (Core, allocation-free recording): nearest-rank p50/p95/p99, max, overruns vs budget, ticks per second; totals across windows.
- `NetworkSimulation.Metrics`; server logs `server_tick_metrics` every 5 s and `server_tick_summary` at shutdown; `VehicleNetworkDriver.SnapshotsSent`.
- `tools/load-test.sh native|docker [bots] [seconds]` → `artifacts/load/summary.json`, `tick_windows.csv`, per-process logs.

## Assertions in the fixture
All N bots spawn and exit cleanly; ≥ 3 metric windows at full load; tick rate ≥ 29 Hz; p95 tick work ≤ 33.3 ms; overruns ≤ 1%; prediction stats reported by every bot.

## Recorded baseline (`docs/perf/VR-013-load-baseline-macos.json`)
macOS arm64 (Apple Silicon), native server + 8 dev bots on the same machine, 40 s, 100 ms simulated RTT, all bots driving.
**Re-recorded after the VR-012 spawn fix**: the first recording had all 8 cars teleported to the origin (stacked), so it understated real spread-out load; the fixture now asserts every car spawns on the grid row (bots drive off at once, so later bots may reuse a freed slot).

| Metric (8 windows at full load, 1,205 ticks) | First run (cars stacked, invalid) | Corrected |
|---|---|---|
| Tick rate (min window) | 29.83 Hz | 29.81 Hz |
| Tick work p50 / p95 / p99 (worst window) | 1.04 / 1.84 / 4.13 ms | 0.98 / 1.61 / 6.21 ms |
| Max tick | 5.88 ms | 15.54 ms |
| Overruns (> 33.3 ms) | 0 | 0 |
| Bot input→ack latency (mean) | 157 ms | 149 ms |
| Bot mean prediction error (worst bot) | 0.068 m | 0.045 m |
| Snaps (worst bot) | 2 | 0 |

Caveat: one machine hosting server + 8 clients; not target server hardware. The CI run (x86-64, Docker) adds a Linux data point on `main`.
