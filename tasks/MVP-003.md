# Task: MVP-003 — Build from the phone; placed blocks are solid

## Goal
A joined player can place and remove blocks from the phone, and every car collides with placed blocks.

## Changes
- **PhoneBuilder** (Presentation, on `NetworkWorld`): the build button cycles Place → Remove → Off. In Place or Remove, a tap off the HUD aims through the synced replica (`VoxelRaycast`) and sends the edit with `WorldSyncClient.SendEdit`. The client pre-checks with `EditValidator`, using the same 1.5 m car-eye reach origin as the server, so failures are explained at once; the server's result replaces the status line.
- **CameraGestures** now reports taps: a touch off the HUD that is shorter than 0.35 s and travels under 25 px. A drag still orbits the camera, and a finger holding gas does not block a tap.
- **WorldColliders** (Gameplay): one mesh collider per non-empty chunk of the synced region, rebuilt with the Burst mesher when a chunk's revision changes (and its face neighbours). The server binds it to the authority (`WorldSyncServer.GetChunk`) and builds everything before any car spawns. Clients bind it to their replica, so prediction collides with the same blocks.
- **CI/test target:** Unity tests run on the Linux64 Player subtarget, because a cached Library left on Dedicated Server compiled out Presentation (CI-001 follow-up).

## Not done
- Block palette: the phone always places brick.
- Edits during a race go to the sandbox world view; race overlays are not drawn separately.

## Verification
- PlayMode 35/35 (new: placed block collides and stops colliding when removed; Client scene has PhoneBuilder and sends nothing offline). EditMode 537/537.
- Native smokes: world (late join and restart hashes), drive (100 ms RTT, speed hack rejected), race (8 racers, reconnect).
