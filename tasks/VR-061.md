# Task: VR-061 — Track revision lock and match-scoped destruction overlay

## Goal
Races can wreck the track without touching the saved sandbox. DoD (BACKLOG): sandbox unchanged after race. Also covers SAVE-007 (match reset never changes the saved world).

## Prerequisites / relevant docs
VR-060 (race phases), DES-002..DES-011 (zones, collisions, explosions, collapse), VR-032/033 (journal, replicas). DESTRUCTION (Race isolation: lock the track revision, write destructible edits to a match overlay, reset on match end, never persist the overlay), ADR-004, GAMEPLAY_RULES (ActiveRace: only pre-tagged race destructibles).

## In scope / out of scope
In: `WorldAuthority.Lock/Unlock/IsLocked` (`race_locked` for client edits and server commits inside a locked region), `ChunkData.Clone`, `MatchWorld` (Begin: verify the track is loaded, record revision + hash per track chunk, clone into an overlay authority with no journal and an optional publish sink, lock the sandbox region; `TouchedChunks`; End: unlock, verify the sandbox track is byte-identical, discard the overlay), `ClientWorldReplica.Fork` (racers apply match deltas to a fork; the sandbox replica never sees them).
Out: NGO message channel for match deltas and the client switching to/from its fork (VR-062), tagging destructibles in track authoring, persisting race results.

## Design notes
- Isolation by construction: the overlay is a separate authority whose only sink is a publisher, so race batches can't reach the journal. The sandbox lock makes the locked revision immutable for the whole race, and `End` re-verifies it (throws on any difference rather than silently keeping race damage).
- Overlay revisions continue from the locked revisions, so racers' forked replicas apply match deltas with the normal gap rules.
- Everything outside the track keeps working and persisting during a race.

## Bug found during validation (fixed in DES-004, merged up)
`ImpactResolver` (DES-003) removed blocks with `ChunkData.Set`, bypassing the authority: collision kills weren't journaled or replicated, so a racer's replica would have diverged. It now commits kills through `CommitServerChanges`.

## Tests (`Tests/Domain/Destruction/RaceOverlayTests.cs`)
- **DoD**: sandbox with a real journal; a brick wall and a tower on the track; countdown → `MatchWorld.Begin`; in the overlay a blast through the wall, a car smashing a block and the tower collapsing (5 blocks); racers' forked replica equals the overlay exactly, no gaps; sandbox refuses client edits and server commits on the track (`race_locked`) and accepts an edit elsewhere; after `End` the track chunks hash exactly as before the race, wall and tower intact, the client's sandbox replica never saw race deltas; after a restart the journal holds only sandbox records (no race or collapse actors) and every chunk reloads to the expected hash.
- Second race starts from the same locked track (wall back); only tagged blocks are destructible in the overlay; begin requires the whole track loaded and locks nothing on failure; end unlocks and is idempotent; tampering with the sandbox during a race is detected at end.
